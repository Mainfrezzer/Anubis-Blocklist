# Anubis Blocklist Generator

An automated GitHub Actions workflow that fetches IP prefixes (IPv4/IPv6) for configured hosting and cloud providers via the RIPEstat API, generating optimized blocklists for Anubis.

## 🚀 How It Works

1. **Automation:** The workflow runs automatically via a daily cron job (at 03:17 UTC) or can be triggered manually using `workflow_dispatch`.
2. **RIPEstat API Integration:** For every configured ASN (Autonomous System Number), the script queries RIPEstat to get the live announced IP prefixes.
3. **Smart Naming:** The generator dynamically resolves the official network holder name from RIPE and automatically strips out annoying duplicate words for clean filenames.
4. **Validation:** Before saving, a validation step tests the structure of the generated YAML files to guarantee they are error-free.
5. **Auto-Commit:** Updated blocklists are automatically committed and pushed back to the repository into the `anubis/list/` directory.

## 📦 Output Files & Structure

All generated blocklists are stored in the `anubis/list/` directory. The workflow creates **one dedicated file per provider** (named after the cleaned RIPE holder title) as well as one **all-in-one blocklist** (`blocklist.yaml`).

### Structure of a generated YAML file
The output format features a nested challenge configuration optimized for firewalls:

## 🛠️ GitHub Actions Workflow Pipeline

The automation pipeline executes the following tasks:
* **Checkout:** Pulls the current state of your repository.
* **Install Python YAML:** Sets up Python3 and the system YAML dependencies.
* **Generate blocklists:** Runs the inline Python script that interacts with the RIPE API, deduplicates strings, and formats the rule objects.
* **Validate YAML:** Assures every produced file exactly matches the expected schema.
* **Commit changes:** Pushes modifications back to your main branch if any IP addresses or prefixes have changed.
